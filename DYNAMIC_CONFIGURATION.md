# Dynamic Configuration from DOM

The lookupToSelect plugin now supports automatic configuration extraction from the existing Power Pages lookup controls in the DOM. This eliminates the need to manually specify entity configurations in most cases.

## How It Works

The plugin automatically:
1. Locates the lookup modal for the target field (`#fieldname_lookupmodal`)
2. Extracts the `data-view-layouts` attribute from the entity grid
3. Parses the base64-encoded JSON metadata
4. Automatically configures entities based on the view layouts
5. **Extracts text field names from the first `Type: 0` column in each view's column metadata**

## Automatic Usage (Recommended)

For most cases, you can now use the plugin with minimal or no configuration:

```javascript
// Automatic configuration - works for both single and polymorphic lookups
$("#sch_personinvolved").lookupToSelect({
    placeholder: "Search for a person..."
});

$("#sch_location").lookupToSelect({
    placeholder: "Search for a location..."
});
```

The plugin will automatically:
- Detect if it's a single entity or polymorphic lookup
- Extract entity names, primary keys, and target table names
- Configure appropriate display names from view names
- Set up proper field mappings

## Manual Configuration (Override)

You can still provide explicit configuration to override the automatic detection:

```javascript
// Manual single entity configuration
$("#contact_lookup").lookupToSelect({
    entitySetName: "contacts",
    idFieldName: "contactid",
    textFieldName: "fullname",
    targetTableLogicalName: "contact"
});

// Manual polymorphic configuration
$("#customer_lookup").lookupToSelect({
    entities: [
        {
            entitySetName: "accounts",
            idFieldName: "accountid",
            textFieldName: "name",
            targetTableLogicalName: "account",
            displayName: "Accounts"
        },
        {
            entitySetName: "contacts", 
            idFieldName: "contactid",
            textFieldName: "fullname",
            targetTableLogicalName: "contact",
            displayName: "Contacts"
        }
    ]
});
```

## Configuration Priority

The plugin uses this priority order:
1. **Explicit configuration** - If you provide `entitySetName`, `entities`, `data`, or `getData`, it uses your configuration
2. **DOM extraction** - If no explicit configuration is found, it extracts from the DOM
3. **Error** - If neither explicit config nor DOM data is available, it throws an error

## Text Field Mapping

The plugin automatically determines the text field using column metadata:

1. **Column Metadata Only** - Extracts the `LogicalName` from the first `Type: 0` (viewColumn) in the view's `Columns` array
2. **No Fallback** - If column metadata is not available or incomplete, the plugin will require manual configuration

This approach ensures the plugin only uses the exact field configured in the Power Pages view layout, eliminating any risk of incorrect field references.

## Entity Set Name Mapping

The plugin automatically converts entity logical names to OData entity set names by adding 's':
- `contact` → `contacts`
- `account` → `accounts`
- `sch_address` → `sch_addresss`

## Error Handling

The plugin provides clear error messages for common issues:

```javascript
// Missing DOM elements
"No configuration provided and unable to extract configuration from DOM. Please provide entitySetName/entities or ensure the lookup modal exists in DOM."

// Invalid view layouts data
"Error parsing view layouts data: [specific error]"

// Missing column metadata (console warning)
"Unable to determine text field for entity 'entityname' - no Type 0 columns found in view layout. Manual configuration required."
```

If the plugin cannot extract valid configuration from the DOM, it will require manual configuration to ensure accuracy and prevent errors.

## Example DOM Structure

The plugin expects the following DOM structure (automatically generated by Power Pages):

```html
<input id="sch_location" type="hidden">
<input id="sch_location_name" type="text">
<input id="sch_location_entityname" type="hidden">

<div id="sch_location_lookupmodal">
    <div class="entity-lookup">
        <div class="entity-grid" 
             data-view-layouts="[base64EncodedViewLayouts]">
            <!-- Grid content -->
        </div>
    </div>
</div>
```

## Migration Guide

### From Manual to Automatic

```javascript
// Before (manual configuration)
$("#sch_location").lookupToSelect({
    entities: [
        {
            entitySetName: "sch_addresss",
            idFieldName: "sch_addressid", 
            textFieldName: "name",
            targetTableLogicalName: "sch_address",
            displayName: "Addresses"
        },
        {
            entitySetName: "sch_offices",
            idFieldName: "sch_officeid",
            textFieldName: "name", 
            targetTableLogicalName: "sch_office",
            displayName: "Offices"
        }
    ]
});

// After (automatic configuration)
$("#sch_location").lookupToSelect({
    placeholder: "Search locations..."
});
```

## Benefits

1. **Reduced Code** - No need to manually specify entity configurations
2. **Maintenance-Free** - Automatically adapts to Power Pages configuration changes
3. **Error-Proof** - Eliminates manual configuration errors
4. **Flexible** - Still supports manual override when needed
5. **Future-Proof** - Works with any entity configuration in Power Pages

## Browser Compatibility

- Requires `atob()` function for base64 decoding (IE10+)
- All other functionality maintains existing browser support
